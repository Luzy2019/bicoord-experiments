# 0607 上午：非对称双臂 AT 方案整理总结

导出时间：2026-06-07  
主题：Action-Time AT、耦合分布散度、紧凑调度、AT2 实验分支实现

---

## 1. 总体目标

本轮讨论围绕非对称双臂 Action-Time 策略展开，目标是让双臂动作生成和紧凑执行解耦：

```text
主模型：只生成动作 A = (A_L, A_R)
调度器：根据耦合、风险、动力学代价生成 compact schedule
执行器：后续消费 schedule，实现真实异步/紧凑执行
```

AT 方案以 `DP_AT` / `FM_AT` 为基础，`DP_WM` 只作为早期参考。WM 中的 `alpha/gate/warp` 路线不应混进 AT 主线，避免研究边界变脏。

## 2. 关键设计结论

### 2.1 不再使用 `loss_marginal - loss_conditional` 作为理论定义

原 README 中写法：

```text
C_{L->R} = loss_marginal_R - loss_conditional_R
C_{R->L} = loss_marginal_L - loss_conditional_L
```

这个只有在 loss 是严格 NLL 且模型充分拟合时，才可近似解释为条件互信息或 KL。当前 DP/FM 辅助分支通常是 MSE denoising / velocity target，因此它更像 predictive gain proxy，不是用户原始想法。

### 2.2 用户原始定义被确认更准确

理论上应写成分布散度：

```text
C_{L->R} = D[p(A_R | A_L, O) || p(A_R | O)]
C_{R->L} = D[p(A_L | A_R, O) || p(A_L | O)]
```

AT2 中采用 diagonal Gaussian KL：

```text
C_{L->R} = KL[p(A_R | A_L, O) || p(A_R | O)]
C_{R->L} = KL[p(A_L | A_R, O) || p(A_L | O)]
```

这样可以同时表达：

- 均值变化
- 方差变化
- 条件分布是否更确定
- conditional information gain / entropy reduction

### 2.3 compact schedule 会接真实执行器

用户明确确认：`compact_schedule` 后续会接入真实执行器。

因此 scheduler 不能只返回 start time，还必须返回执行时长和加速比例：

```text
compact_schedule
compact_schedule_durations
compact_schedule_ends
compact_schedule_speed_scale
```

加速比例定义为：

```text
speed_scale = base_dt / duration
```

目前加速多少由 scheduler 搜索决定，而不是直接由 cond/marginal 决定。coupling score 只影响调度代价。

### 2.4 chunk-level KL 比 per-step KL 更适合做主指标

最新讨论结论：

- 如果执行器按 action chunk 执行，那么主理论定义更应该是 chunk-level KL：

```text
C_{L->R} = KL[p(A_R^{1:H} | A_L^{1:H}, O) || p(A_R^{1:H} | O)]
C_{R->L} = KL[p(A_L^{1:H} | A_R^{1:H}, O) || p(A_L^{1:H} | O)]
```

- per-step KL 仍有价值，适合 scheduler 做局部 timing / duration / sync cost。
- 推荐下一步在 AT2 中保留：

```text
coupling_scores: [B, T, 2]        # per-step KL, 给 scheduler 用
coupling_chunk_scores: [B, 2]     # chunk-level KL, 给日志/论文/候选整体判断用
```

chunk score 可先用：

```text
coupling_chunk_scores = coupling_scores.mean(dim=1)
```

必要时再同时记录 max 或 p90，避免短暂高耦合被均值稀释。

## 3. 已实现内容

按照用户要求，没有直接修改现有 baseline：

```text
policy/DP_AT
policy/FM_AT
```

而是完整复制出新实验分支：

```text
policy/DP_AT2
policy/FM_AT2
```

### 3.1 新分支结构

新增目录：

- `policy/DP_AT2`
- `policy/FM_AT2`

新增 AT2 config：

- `policy/DP_AT2/diffusion_policy/config/robot_dp_at2_16.yaml`
- `policy/FM_AT2/flow_matching_policy/config/robot_fm_at2_16.yaml`

更新 AT2 README：

- `policy/DP_AT2/README_AT.md`
- `policy/FM_AT2/README_AT.md`

### 3.2 Coupling estimator 改为 Gaussian KL

在 AT2 的核心 policy 中实现：

- `DiagonalGaussianActionHead`
- 新版 `BimanualCouplingEstimator`
- `_gaussian_nll`
- `_gaussian_kl`

每个分布 head 输出：

```text
mu, logvar
```

其中 `logvar` 被 clamp 到：

```text
[-10, 5]
```

训练目标：

```text
Gaussian NLL on clean normalized action chunks
```

推理耦合：

```text
KL[p_cond || p_marg]
```

### 3.3 DP_AT2 / FM_AT2 都使用 clean normalized action 训练 coupling

DP_AT2 不再用 diffusion epsilon/sample target 训练 coupling estimator。  
FM_AT2 不再用 flow velocity target 训练 coupling estimator。

也就是说，T3 学的是：

```text
p(A_arm | ...)
```

而不是：

```text
p(noise/velocity | ...)
```

这让代码语义和理论定义一致。

### 3.4 Scheduler 返回真实执行器字段

AT2 的 `predict_action` 现在返回：

```text
action
action_pred
compact_schedule
compact_schedule_durations
compact_schedule_ends
compact_schedule_speed_scale
makespan
coupling_scores
candidate_scores
wm_scores
energy_scores
dependency_cost
dynamics_cost
collision_or_risk_cost
```

`compact_schedule` 仍是 start times，用于兼容旧接口。新增字段用于真实异步执行器。

### 3.5 训练和评估入口改为 AT2

已在 AT2 中更新：

- `train_at.sh` 默认使用 AT2 config
- exp name 改为 `*_at2_kl`
- `deploy_policy.yml` 中 policy name 改为 `DP_AT2` / `FM_AT2`
- eval / double-env / interactive 脚本的 policy name 和 checkpoint path 改为 AT2

## 5. 当前待办建议

下一步最建议补的是 chunk-level KL：

1. 在 AT2 的 `_score_action` 中基于 per-step `coupling_scores` 增加：

```text
coupling_chunk_scores = coupling_scores.mean(dim=1)
```

2. 在 `predict_action` 返回：

```text
coupling_chunk_scores
```

3. README 主定义改成 chunk-level KL，per-step KL 作为 factorized temporal decomposition。

4. 可选：同时记录峰值耦合：

```text
coupling_chunk_max = coupling_scores.max(dim=1).values
```

5. scheduler 暂时继续用 per-step KL 做局部调度；后续可考虑：

```text
C_schedule = mean_t(KL_t) + beta * max_t(KL_t)
```

这样同时兼顾整体耦合和短时强耦合。

## 6. 最终状态

当前 AT2 已经完成“从 proxy 到真实分布散度”的第一版实现：

```text
旧版：
loss_m - loss_cond
或
||f_cond - f_marginal||^2

新版 AT2：
KL[p_conditional_action_distribution || p_marginal_action_distribution]
```

但理论表述上，chunk-level KL 更适合作为最终主指标。当前 per-step KL 适合 scheduler 使用，下一步应补充 `coupling_chunk_scores`，把 README 和输出接口进一步对齐到 action chunk 执行语义。
