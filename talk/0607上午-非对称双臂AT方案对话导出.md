## 1. DP、LeWorldModel、V-JEPA 的结合

用户最初关注 `policy/DP` 中原始 Diffusion Policy 的实现，希望思考是否能加入 LeWorldModel 或 V-JEPA。

讨论结论：

- V-JEPA 更适合作为视觉编码器或 video latent encoder，替换/增强 DP 的 `obs_encoder`。
- LeWorldModel 更适合作为 latent dynamics 辅助任务：

```text
z_t = encoder(o_t)
z_hat_{t+1} = f(z_t, a_t)
L_world = ||z_hat_{t+1} - z_{t+1}||^2 + Gaussian regularizer
```

- 如果只是加 world-model auxiliary loss，它更像 model-augmented behavior cloning。
- 如果 world model 参与 action proposal rerank、MPC、reward/goal scoring，就接近 model-based planning / model-based RL。

核心判断：

```text
LeWorldModel 和 model-based RL 的“模型部分”高度同构；
区别在于是否用模型参与 reward-driven policy improvement。
```

## 2. 三类 latent world/generative model 范式

用户提出三类理解：

1. latent space -> predict next images，例如 NVIDIA Cosmos。
2. latent space -> predict next latent space，例如 LeWorldModel。
3. latent space -> predict reward，例如 Dreamer。

讨论修正：

- Cosmos 更像 visual future / Video2World generation，不只是 next image。
- LeWorldModel / JEPA 是 latent predictive model，不重建像素，预测未来 embedding。
- Dreamer 不是单纯 `latent -> reward`，而是：

```text
obs -> latent
latent + action -> next latent
latent -> reward / continue / value
actor 在 imagined latent rollout 中训练
```

## 3. 非对称双臂解耦 markdown 思想

阅读 `policy/DP_RL` 下相关 markdown 后，提炼出核心数学思想：

三种策略结构：

```text
A: joint policy
   p(a_L, a_R | O)

B: conditional / leader-follower
   p(a_L | O) p(a_R | a_L, O)

C: independent local policy
   p(a_L | s_L) p(a_R | s_R)
```

统一为能量/残差递进：

```text
log p(a_L, a_R | O)
= log p(a_L | s_L)
+ log p(a_R | s_R)
+ R_obs_L
+ R_obs_R
+ R_coup
```

其中：

- `R_obs` 表示跨臂观测残差。
- `R_coup` 表示动作耦合残差。
- 残差小的时候退化为独立局部方案 C。
- 残差大时需要进入条件或联合策略。

用户原本想用 KL / entropy / distribution divergence 来衡量耦合强度。讨论认为更严谨的表达应是：

```text
C_{L->R} = D[p(a_R | a_L, O) || p(a_R | O)]
C_{R->L} = D[p(a_L | a_R, O) || p(a_L | O)]
```

工程上可用 denoiser / velocity 输出差异做代理：

```text
C_{L->R} ≈ ||f_R^cond - f_R^marginal||^2
C_{R->L} ≈ ||f_L^cond - f_L^marginal||^2
```

但这只是 distribution divergence / entropy reduction 的 surrogate，不应写成严格 KL。

## 4. EBM / FM 是否能被 RL 或 WM 改变

用户提出：

1. 如果使用能量模型，学习的是能量场，能否通过 RL 或 WM 影响目标能量场？
2. 如果使用 Flow Matching，学习的是向量场，能否通过 RL 或 WM 改变向量场方向？

讨论结论：

### EBM

能量可以被 reward / WM 重新倾斜：

```text
E_total(A | O)
= E_data(A | O)
+ λ_goal E_goal(A, O)
+ λ_dyn E_dyn(A)
+ λ_safe E_safe(A)
- β Q_WM(A, O)
```

等价于：

```text
π(a | O) ∝ exp(-E_data(a,O) + β Q(a,O))
```

高价值动作被压低能量，低价值动作被抬高能量。

### Flow Matching

Flow Matching 可以通过两种方式改向量场：

1. 训练时改变目标分布：

```text
p_new(a | O) ∝ p_demo(a | O) exp(β Q_WM(a,O))
```

然后训练新 flow：

```text
v_new = v_demo + Δv_RL/WM
```

2. 推理时 guidance：

```text
v_guided = v_BC + λ ∇_a Q_WM(a,O)
```

或能量形式：

```text
v_guided = v_BC - λ ∇_a E_WM(a,O)
```

约束条件：

```text
L = L_FM
  + λ_RL L_reward
  + λ_WM L_world
  + λ_trust ||Δv||²
  + λ_manifold E_data
```

## 5. “耦合不紧时可以并行执行”的前提

用户提出核心问题：

> 两个臂耦合不紧凑的时候，应该可以并行执行任务/动作。训练数据里没有这种“紧凑执行任务”的轨迹，是否可以通过调整能量场或加速场生成紧凑轨迹？

讨论判断：

这个前提成立，但要加约束：

```text
可以并行 ≠ 任意并行
```

必须满足：

- 不碰撞。
- 不破坏接触顺序。
- 不共享同一物体的互斥阶段。
- 不违反动力学约束。
- 不降低任务成功率。

真正难点：

```text
紧凑轨迹不存在于 demo 中；
它是反事实的、理想的、没有直接监督标签。
```

因此紧凑性不能直接监督学习，而应定义为 constrained optimization：

```text
maximize    task_success(Y)
            - λ_time * execution_time(Y)
            - λ_coll * collision(Y)
            - λ_ood * out_of_demo_manifold(Y)
            - λ_sync * precedence_violation(Y)
            - λ_dyn * dynamics_violation(Y)
```

其中：

```text
Y = (A_L, A_R, timing_L, timing_R)
```

核心结论：

```text
紧凑性不是数据标签，而是目标函数；
WM/RL 的作用是把这个目标函数变成可搜索、可验证、可蒸馏的信号。
```

## 6. alpha 和 gate 的问题

早期方案里出现了：

```text
dz_L/dt = α_L(z,o) v_L(z,o)
dz_R/dt = α_R(z,o) v_R(z,o)
```

以及：

```text
v = v_local + g * residual
```

用户质疑：

> alpha 和门控并不是很好的设计，感觉不像直接用 Flow Matching 或 EBM 的动作生成方式，更像硬编码 / 工程化实现。

讨论认可这个质疑：

- `alpha * v` 存在尺度不可辨识：

```text
alpha * v = (alpha / c) * (c v)
```

- 显式 gate 是人为结构假设：

```text
v = v_local + g * residual
```

- 它们适合做 early baseline / diagnostic tool，但不够优雅。

更优雅的方向：

```text
不要加速一条已有轨迹；
直接生成动作 + 时间结构。
```

## 7. 最终推荐方案：Action-Time Joint Generation

最终确定不用 alpha、不用显式 gate，而是让模型直接生成：

```text
Y = (A_L, A_R, t_L, t_R)
```

其中：

- `A_L, A_R` 是左右臂 action chunk。
- `t_L, t_R` 是左右臂对应动作的执行时间戳、duration 或 event schedule。

### EBM 形式

```text
E(Y | O)
= E_demo_path(A_L, A_R | O)
+ E_WM_failure(Y, O)
+ E_collision(Y)
+ E_precedence(Y)
+ E_dyn(Y)
+ λ_time * makespan(Y)
```

推理：

```text
Y* = argmin E(Y | O)
```

### Flow Matching 形式

```text
noise -> (A_L, A_R, t_L, t_R)
```

训练 compact target distribution：

```text
p_compact(Y | O)
∝ p_demo(Y | O)
  exp(reward_success(Y)
      - λ_time * makespan(Y)
      - λ_risk * risk(Y))
```

### 最小可行闭环

```text
1. Demo -> train base DP/FM
2. Base policy 生成 action-time candidates
3. Sim/WM rollout 打分
4. reward = success - λ_time * makespan - penalties
5. 保存高分 compact trace
6. 蒸馏回 Action-Time DP/FM
```

核心判断：

```text
先 imitation 保成功；
再 model-based improvement 找紧凑；
最后 distill 成直接生成 compact trace 的模型。
```

## 8. 训练过程中学加速，还是像 RL 一样后续进化？

用户问：

> 是在训练过程中学习这种加速，还是先学一个成功模型作为下限，然后在仿真环境或世界模型中不断交互、不断进化？

讨论结论：

更推荐第二种：

```text
先学稳定成功 base model，
再在 sim / WM 中搜索、验证、蒸馏紧凑轨迹。
```

原因：

- 原 demo 没有 compact target。
- 从零端到端加速容易破坏成功率。
- BC 想贴近 demo，compactness 想偏离 demo 的时间结构，目标冲突。

推荐路线：

```text
Base Flow/DP
-> sample K action candidates
-> generate multiple left/right timing schedules
-> sim/WM rollout score
-> select high-success low-time traces
-> train Action-Time Flow/DP
```

## 10. 当前实现边界

当前 AT 分支完成的是：

```text
action-time generation + verifier/rerank + distillation interface
```

但需要注意：

- 如果环境仍只接受同步 16D action，则 `time_trace` 暂时主要用于日志、rerank 和后续蒸馏。
- 真正物理层面的异步执行，需要 deploy/eval 层消费 `time_trace`。
- compact trajectory 的有效监督信号仍需来自：

```text
sim search / WM rollout / RL improvement / pseudo-label distillation
```

所以研究叙述上应该避免说：

```text
模型直接从原始 demo 学出了紧凑执行。
```

更准确：

```text
模型先学 demo action-time base distribution；
compact trace 通过 success-constrained time optimization 生成；
再蒸馏回 action-time generative policy。
```

## 11. 后续最重要的实验问题

1. `time_trace` 是否接入真实执行器？
   - 如果不接，只能证明 compact-aware reranking。
   - 如果接入，才能证明真实 makespan 缩短。

2. compact candidate 如何生成？
   - 固定 schedule search。
   - CEM / MPC search。
   - learned scheduler。
   - dependency graph scheduler。

3. WM verifier 是否可靠？
   - 需要用 sim/rollout 校验 WM score 和真实 success 的相关性。

4. 如何证明不是简单加速？
   - 对比 `alpha/warp` baseline。
   - 对比 uniform downsample。
   - 对比原 DP/FM。
   - 对比 action-only rerank。

## 12. 一句话总结

最终方案不是：

```text
alpha * velocity
```

也不是：

```text
local + gate * residual
```

而是：

```text
直接生成动作-时间联合 trace：
Y = (A_L, A_R, t_L, t_R)
```

紧凑性来自：

```text
成功约束下最小化 makespan
```

学习闭环是：

```text
demo imitation
-> WM/sim/RL search
-> compact pseudo-label
-> action-time DP/FM distillation
```
